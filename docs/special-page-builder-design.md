# 特設ページ作成支援UI 設計案

## 目的

`kaguya.html` のような音楽作品向け特設ページを、管理画面から編集してフォルダ単位で生成できるようにする。
既存の検索・リクエスト・プレイヤー系ツールとは分離し、生成物をいつでも削除・差し替え・復元できる構造にする。

完成イメージは、添付3枚目のような「音楽作品ポータルLP」を自由に編集できる状態を目標にする。
現在のカード一覧/歌手別アコーディオンは素材として活かしつつ、トップビューはヒーローカルーセル、下部にPICKUP/ARTIST/SONGSを並べる構成へ発展させる。

参考:

- `https://www.cho-kaguyahime.com/` は NEWS / MOVIE / INTRODUCTION / STORY / MUSIC / CHARACTER / STAFF/CAST を持つ作品LP型。
- `https://www.swordart-online.net/` は作品シリーズ/商品/配信/ゲーム導線を持つポータル型。
- 今回はこの中間として、MUSIC中心のポータルLPに寄せる。

## 基本方針

- 既存ページを直接上書きしない。
- 編集データはJSONで保存し、生成HTML/CSS/JS/assetsは特設ページごとのフォルダに出力する。
- 初期実装は静的生成を基本にし、PHPの実行コードを生成物に混ぜない。
- デザインはテンプレート/セクション/プリセットの組み合わせで拡張する。
- 復元できるように、生成ごとにスナップショットを残す。

## 編集画面

### 1. プロジェクト一覧

- 新規作成
- 既存プロジェクトを編集
- プレビュー
- フォルダ生成
- スナップショット復元
- ZIPエクスポート

### 2. 基本設定

- スラッグ
- ページタイトル
- ロゴ画像
- OGP画像
- 公開/非公開
- 出力先フォルダ

スラッグは `a-z0-9-_` のみに制限し、既存フォルダの上書きは確認を必須にする。

### 3. デザイン

色指定プリセットは複数選択できるようにする。
単一テーマではなく、選択したプリセットを上から順にCSS変数へ合成する。

お任せ10種類:

1. `moonlight_blue` 月光ブルー: 濃紺、青白い光、静かな夜景向け。
2. `sakura_neon` 桜ネオン: ピンク、紫、ライブ演出向け。
3. `kaguya_gold` かぐやゴールド: 金、薄桜、和風タイトル向け。
4. `cyber_lime` サイバーライム: 青緑、蛍光、ゲーム/電脳感向け。
5. `crimson_stage` 紅ステージ: 深紅、黒、強いライブ感向け。
6. `snow_prism` 雪プリズム: 水色、白、透明感のある曲向け。
7. `twilight_orange` 夕景オレンジ: 夕焼け、琥珀、エモーショナル系。
8. `violet_magic` 紫魔法: 紫、銀、幻想系。
9. `mono_luxury` モノクロ高級感: 黒、白、細い金線。
10. `idol_pop` アイドルポップ: 明るいピンク、シアン、白。

プリセット合成ルール:

- 1つ目をベース色にする。
- 2つ目をアクセント色にする。
- 3つ目以降はタグ色、グロー、ボタン色に割り当てる。
- 手動上書きは最後に適用する。

編集できる項目:

- 背景画像
- 背景の暗さ
- 背景ぼかし
- カード透過度
- カード角丸
- グロー強度
- 見出しフォント
- 本文フォント
- ナビの表示項目
- スマホ時に表示するナビ項目

### 4. レイアウト

テンプレート単位で編集する。
初期テンプレートは `Moonlight Music Portal`。

セクション:

- TOP: 横スワイプ式ヒーローカルーセル
- PICKUP: coverflowカード
- ARTIST: アーティストカード+展開式トラックリスト
- SONGS: フィルター付き楽曲一覧
- UNIT: ユニット一覧
- CREDIT: クレジット/リンク集

各セクションで編集できるもの:

- 表示/非表示
- 並び順
- 見出しテキスト
- 表示件数
- カードサイズ
- 画像比率
- PC/スマホ別レイアウト

### 5. コンテンツ

楽曲:

- 曲名
- 読み
- 歌手
- CV
- タイプ: solo / duet / unit / group / cv
- タグ
- ジャケット
- 再生リンク
- 歌詞リンク
- 検索リンク

歌手:

- 名前
- 読み
- CV
- アイコン
- 所属ユニット
- 担当曲

ユニット:

- ユニット名
- メンバー
- 代表曲
- 画像

### 6. プレビュー

- PCプレビュー
- スマホプレビュー
- 背景の視認性チェック
- 長い曲名の折り返しチェック
- 画像未設定チェック
- リンク切れチェック

プレビューは iframe で隔離し、既存の管理画面CSSと混ざらないようにする。

## 生成処理

生成ボタンを押したときの流れ:

1. 入力値を検証する。
2. 現在の `manifest.json` / `theme.json` / `content.json` をスナップショットへ退避する。
3. テンプレートとJSONから `index.html` を生成する。
4. 必要なCSS/JS/assetsだけを出力する。
5. `special_pages/{slug}/index.html` へのリンクを表示する。

生成物は静的HTMLにする。
管理画面のPHPや設定ファイルへ依存しないため、壊れてもフォルダごと戻せる。

## 実装案

### 案A: JSON編集+テンプレート生成

低リスク。
フォームで各項目を編集し、テンプレートに流し込んで静的HTMLを生成する。

メリット:

- 既存機能への影響が小さい。
- 本家に説明しやすい。
- 復元しやすい。

デメリット:

- ドラッグ&ドロップ編集の自由度は低い。

### 案B: セクションビルダー

中リスク。
TOP/PICKUP/ARTIST/SONGSなどのセクションを追加・並べ替えできる。

メリット:

- 拡張性が高い。
- テンプレートを増やしやすい。

デメリット:

- UI設計と保存スキーマがやや複雑になる。

### 案C: 完全WYSIWYG

高リスク。
カードや画像を自由配置する。

メリット:

- 自由度が最も高い。

デメリット:

- スマホ対応、復元、壊れにくさの担保が難しい。
- 本家採用には説明が重くなる。

## 推奨ロードマップ

1. 案Aで最小実装する。
2. セクション順序、表示/非表示、画像アップロード、プリセット複数選択を入れる。
3. 案Bとしてセクション追加と並び替えを足す。
4. WYSIWYGは最後に限定機能として検討する。

## 現在の実装メモ

今回の実装は案Aを採用する。

追加した画面:

- `special_page_builder.php`: 環境設定から開く編集画面。
- `special_page_preview.php`: 保存済みJSONを隔離表示するプレビュー画面。
- `special_page_func.php`: JSON保存、スナップショット、静的HTML生成、プリセット定義。
- `css/themes/special-builder.css`: 編集画面用CSS。
- `js/special_page_builder.js`: 楽曲/歌手の行追加・削除。

現在できること:

- 基本情報、背景、クレジットを編集できる。
- 色プリセット10種類を複数選択できる。
- ボタン色、ボタン文字色、カード画像の表示方法を編集できる。
- ボタンは単色/グラデーションを切り替えられる。
- つや感の有効/無効を選べる。
- PICKUP表示形式はカードグリッド/横スクロール/コンパクトから選べる。
- 全体レイアウトは標準カタログ/左縦PICKUP+中央ビジュアルから選べる。
- カード画像比率とカード高さを調整できる。
- 演出テンプレートはなし/音符/光ライン/ひし形アクセントから選べる。
- 背景は静止画に加えて、明示オン時のみ動画ループを使える。
- 背景動画は `preload="metadata"` とし、未設定時やオフ時は静止画を使う。
- 楽曲と歌手/ユニットをフォームから追加できる。
- 楽曲と歌手/ユニットはドラッグで並び替えできる。
- 楽曲と歌手/ユニットはCSV取込、様式CSV出力、現在値CSV出力ができる。
- 楽曲ごとにPICKUP表示の有無を指定できる。
- `special_pages/{slug}/manifest.json` / `theme.json` / `content.json` に保存する。
- `special_pages/{slug}/index.html` を静的HTMLとして生成する。
- 保存/生成時に `snapshots/` へ既存ファイルを退避する。

PICKUPの基準:

- 楽曲編集画面で `PICKUP表示` を `表示する` にした曲だけを表示する。
- 1曲も指定されていない場合のみ、保険として先頭6曲を表示する。
- 上段に同じ曲を重複表示するラインナップレールは置かない。

生成テンプレートの方向性:

- `kaguya.html` のように、PICKUPは16:9ジャケット付きカードグリッドにする。
- ARTISTは画像をカード内に埋め込み、背景は画像ではなくテーマ色で塗る。
- SONGSは一覧性と検索導線を優先する。
- 装飾目的のヒーローや意味の薄い上段サムネイルは避ける。
- `swordart-online.net` のようなポータル型の考え方は、SERIES/PRODUCTSのように入口をカテゴリ化する部分だけ参考にする。
- レイアウト2は `swordart-online.net` のような左縦ピックアップ+中央ビジュアルの見せ方を、検索導線向けに簡略化して採用する。

案Bへ伸ばすために残している余地:

- `content.nav` とセクション定義はJSON側に残している。
- テンプレート名は `manifest.template` として保存している。
- 画像はパス指定から始め、後続で `assets/bg` / `assets/cover` / `assets/artist` へのアップロードに拡張できる。
- 生成HTMLはPHPに依存しないため、別テンプレートやZIP出力に分岐しやすい。

## 設計の再整理: ポータル型へのオーバーホール

### 診断

現状の生成物は、同じカード文法を繰り返す一覧としては整っている。一方、公式ポータルに見られる完成度は、カードを増やすことではなく、ページ全体がひとつの状態として連動し、セクションごとに役割と構成を変えることで生まれている。特に、選択中の楽曲、ビジュアル、説明、導線、進行表示が同じ視線の流れを作る必要がある。

### 目標パイプライン

将来の生成処理は、入力データをそのままテンプレートへ流し込まず、次の段階を明示する。

```text
JSON -> migrate -> normalize -> validate -> view model -> layout preset -> static HTML
```

- `migrate`: 旧スキーマを新スキーマへ段階的に変換する。
- `normalize`: 欠損値、表記、参照、順序を表示前に統一する。
- `validate`: ID、参照先、必須メディア、URL、アクセシビリティ上の制約を検査する。
- `view model`: 表示用に選択状態、ラベル、導線、メディア、進行情報を組み立てる。
- `layout preset`: セクションの構造と連動方法を決める。
- `static HTML`: 実行時DBやPHPに依存しない生成物へ出力する。

### v2スキーマの方向性（ロードマップ）

v2では、次の概念を導入する。現行スキーマとの移行方法と互換性を確認してから実装するものであり、現時点で未実装である。

- すべての主要エンティティとセクションに変更に強い安定IDを持たせる。
- セクションを配列として順序付きで定義し、表示/非表示とレイアウト設定を分離する。
- 歌手と楽曲の関係を文字列の重複ではなく、明示的な関連として保持する。
- メディアに焦点位置、代替テキスト、用途別バリアントを持たせる。
- 状態遷移に必要なモーションと、背景などの環境的なモーションを区別する。
- `prefers-reduced-motion` を含む、動きを抑えた表示方針をスキーマとプリセットで扱う。

### 構造プリセット

v2以降の構造プリセット候補は次の3つとする。既存の標準カタログやレイアウト2などのレガシーレイアウトは、移行後も同じ入力を扱える互換層を設けて残す。

- `spotlight_rail`: 選択中の主役と横方向の選択レールを同期する。
- `cinematic_chapters`: 章単位の物語進行とビジュアルを同期する。
- `poster_directory`: ポスター型の一覧性と分類・検索導線を優先する。

### 現在実装する最初の垂直スライス

最初に実装するのは `spotlight_rail` のみである。これはv2全体の完成を意味せず、ポータル型の連動を検証するための限定スライスとする。

- 大きなヒーロー、選択レール、CTAを同じ選択状態に同期する。
- 現在位置を示す進行表示を出す。
- キーボード操作で選択と移動ができるようにする。
- タッチ端末ではスワイプで選択できるようにする。
- 各セクションへ直接移動できるアンカーを提供する。

### 検証マトリクス

垂直スライスごとに、少なくとも次の観点で確認する。

| 観点 | 確認内容 |
| --- | --- |
| デスクトップ | ヒーロー、レール、CTA、進行表示の同期、キーボード操作、アンカー |
| モバイル | スワイプ、折り返し、タップ領域、縦長画面での視認性 |
| アクセシビリティ | フォーカス順、名前付き操作、代替テキスト、コントラスト、reduced-motion方針 |
| パフォーマンス | 初期表示、画像バリアント、不要なメディア読込、静的生成物のサイズ |

### 非目標

- 自由配置を行う完全なWYSIWYGエディタは作らない。
- 生成データから任意スクリプトを実行できる仕組みは持たない。
- CDNを必須の実行時依存にしない。
- 実行時DBへ同じコンテンツを複製しない。

## 復元・安全設計

- 生成前に必ずスナップショットを作る。
- `special_pages/{slug}` 以外には出力しない。
- スラッグに `..` や `/` を許可しない。
- 画像は `jpg/png/webp/gif` のみ許可する。
- 生成HTMLに任意PHPを含めない。
- 外部リンクはURL形式を検証する。
- 削除は即時削除せず、まず `disabled` または `trash` へ移動する。

## 本家向けの説明軸

この機能は既存検索/リクエスト処理とは独立した「静的特設ページ生成」機能として切り出す。
設定・データ・生成物をフォルダ単位で分けるため、既存機能の互換性を壊しにくい。
初期実装は案Aに絞り、テンプレートとJSONスキーマを安定させてから、案Bのセクションビルダーへ拡張する。

## 結論

最初から完全自由配置を作るより、`Moonlight Music Portal` テンプレートを中心に、データ入力・プリセット複数選択・静的生成・復元を先に作るのがよい。
これなら添付3枚目のような完成イメージに近づけつつ、既存ツールを壊さず、あとからセクション追加や別テンプレートへ拡張できる。

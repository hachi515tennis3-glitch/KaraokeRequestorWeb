ゆかナビ遮断スイッチ

モバイルアプリ「ゆかナビ」からのアクセスを設定ひとつで止め、端末には 「ゆかナビからのアクセスをオフにしています」を返して Web 版の検索画面へ 自動ジャンプさせます。修正した 5 ファイルの変更前・変更後をそのまま載せています。

新規 1 ファイル 修正 4 ファイル 設定キー 5 個 既定は OFF

01遮断のしくみ

ゆかナビは Unity 製で、ネイティブの API 呼び出しも内蔵ブラウザも UnityPlayer/6000.3.19f1 (UnityWebRequest/1.0, libcurl/8.10.1-DEV) という User-Agent を送ります（Apache のアクセスログで確認）。この文字列を目印に、リクエストの入口で振り分けます。

入口 commonfunc.php 全ページ・全 API が読み込むファイル。先頭で appblock_guard() を呼ぶだけで、遮断の判断を一箇所に集約できます。
遮断 A /api/ 配下 → JSON アプリ専用 API。{"ok":false,"error":"…","redirect":"…"} を返し、ネイティブ機能はここで止まります。
遮断 B Web ページ → 案内 HTML メッセージを表示し、meta refresh と location.replace で 3 秒後にジャンプ先へ飛ばします。
通す ジャンプ先と、案内表示後の端末 ジャンプ先ページ自身は対象外。案内を出した端末には Cookie を発行し、以後の Web ページは通します。

ジャンプ先を遮断対象から外している理由

ジャンプ先の search_bs5.php まで遮断すると「遮断 → ジャンプ → また遮断」で無限ループになります。 さらに、案内を出したあとも遮断し続けると、飛ばした先で曲を予約できず誘導そのものが無意味になります。 そこで案内ページで Cookie YkariAppWebFallback を発行し、 アプリのネイティブ機能だけを止めて Web 版は使えるようにしています。

02追加した設定項目

設定画面の「動作設定 > アプリ接続設定（ゆかナビ）」から変更できます。 config.ini の値は他の設定と同じく URL エンコードで保存されます。

キー既定値意味
appblock 0 遮断の ON / OFF。0 のあいだは何も起きませんので、更新しただけでは今までどおりです。
appblock_web 1 Web ページも遮断するか。0 にすると /api/（アプリ専用 API）だけを止め、アプリ内ブラウザは素通りします。
appblock_msg ゆかナビからのアクセスをオフにしています 端末に返すメッセージ。JSON の error と案内ページの見出しの両方になります。
appblock_url http://ykr.moe:11059/search_bs5.php 自動ジャンプ先。ここに指定したページは遮断対象から外れます。
appblock_ua UnityPlayer|YukaNavi|ゆかナビ アプリ判定に使う User-Agent の正規表現。縦棒区切りで複数指定できます。

04HTTP 200 で返している理由

403 にすると、設定したメッセージが端末に届かないことがあります

Unity の UnityWebRequest をはじめ、多くの HTTP クライアントは 4xx を 「通信エラー」として扱い、レスポンスの中身を読まずに独自の文言を表示します。 それでは appblock_msg に設定した文章が画面に出ません。 /api/ の失敗はもともと HTTP コードではなくエンベロープの ok:false で表す仕様（api/README.md）なので、 200 と ok:false の組み合わせが一番確実にメッセージを届けられます。

05動作確認

XAMPP の実サーバー（http://localhost/）に対して、実際のゆかナビと同じ User-Agent を付けた curl で確認しました。確認後は config.ini を元に戻しています。

  • OK アプリ UA で /api/server_info.php → 遮断 JSON {"ok":false,"error":"ゆかナビからのアクセスをオフにしています","blocked":"appblock","redirect":"…"}
  • OK 通常のブラウザ UA → これまでどおり {"ok":true,"data":{"app":"yukari","version":"v0.10.0-beta-111-g4689167-つぼはち改良",…}}
  • OK アプリ UA で /requestlist_only.php → 案内 HTML meta refresh と location.replace の両方を出力し、Set-Cookie: YkariAppWebFallback=1 も付与
  • OK アプリ UA でもジャンプ先 search_bs5.php は素通り 110,773 バイトの通常ページが返り、無限ループしない
  • OK Cookie 付きの再アクセスは素通り 案内を見たあとは Web 版として通常どおり操作できる
  • OK appblock_web=0 で Web ページは素通り、/api/ は遮断 appblock_ua を書き換えると判定対象も追随することを確認

06使うときの注意

User-Agent 判定なので、詐称すれば通せます

目的は「アプリ利用者を Web 版へ案内すること」であって、不正アクセスの防止ではありません。 確実に締め出したい場合は、Apache 側やファイアウォールでの制限を併用してください。 また UnityPlayer は Unity 製アプリ全般が送る文字列です。 ゆかナビだけを狙いたい場合は、アプリが専用の User-Agent を送るようになった時点で appblock_ua をその文字列に絞ってください。
